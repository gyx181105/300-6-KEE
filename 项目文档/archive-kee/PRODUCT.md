# 产品定位

> 真源。与代码/排期冲突时以此为准。

## 一句话

**KEE 是通用、可进化的知识库系统：用户自建任意知识库，系统持续吸收资料、维护可追溯知识，并通过 API / MCP / 对话为 LLM 与 Agent 提供可信知识服务。**

## 是什么

| 是 | 不是 |
|---|---|
| 多租户、多知识库的知识工程引擎 | 某个行业的垂直应用（医疗/法律/…） |
| 上传资料 → 解析 → 抽取 → 本体/规则 → 审核 → 检索/问答 | 第二套「行业后端」或按行业拆进程 |
| 为 LLM 提供带证据、可治理的知识与工具面（含 MCP） | 仅向量库或仅聊天包装 |
| 领域差异靠用户资料、规则与内容包 | Core 里硬编码行业概念 |

## 谁用

- **建库者**：建 KB、接入来源、配本体/规则、审核发布。  
- **LLM / Agent**：经检索、图谱、RAG、MCP 工具消费已发布知识。  
- **运维**：单栈部署（Rust Core + Postgres + `web/`）。

## 组织模型（现行）

| 层 | 作用 |
|---|---|
| **知识库** | 给 LLM / MCP / 权限的边界；要更细隔离就再建一个库 |
| **Uploads** | 库内默认落点；无来源文档都在这里 |
| **文件夹** | `kind=folder` 来源，**与 Uploads 并列**，只做整理与定向上传 |

不做文件夹嵌套（无 `parent_id`）。更深目录诉求先用多 KB 或并列文件夹解决。

主闭环：**建库 →（可选建文件夹）→ 上传 → 配模型 → 对话 / MCP**。
