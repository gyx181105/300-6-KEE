要搬的是两样东西：Postgres 里的账号、知识库和配置，以及项目目录下的 `data/`（原文、全文索引，还有 `secret.key`）。代码仓库本身不含这些数据，项目也还没有现成的备份命令。

在这台机器上，先停掉 `utopia-server`，只留数据库，然后在项目根目录执行：

```bash
docker compose exec -T db pg_dump -U utopia -Fc utopia > kee.dump
tar czf kee-data.tgz data
```

把 `kee.dump` 和 `kee-data.tgz` 拷到新机器的项目根目录。两边用同一套代码或镜像。数据库迁移只向前滚，新机器的版本不能比这台旧。

在新机器上，如果库已经空跑过一次，先清掉那个空库再导入：

```bash
docker compose stop app
docker compose up -d db
docker compose exec -T db psql -U utopia -d postgres -c "DROP DATABASE IF EXISTS utopia;"
docker compose exec -T db psql -U utopia -d postgres -c "CREATE DATABASE utopia OWNER utopia;"
docker compose exec -T db pg_restore -U utopia -d utopia --no-owner < kee.dump
tar xzf kee-data.tgz
docker compose --profile app up -d
```

如果新机器是用 `cargo run` 起的后端，解压后的 `data/` 要放在启动命令的工作目录下，然后重新 `cargo run -p utopia-server`。

`data/secret.key` 必须一起带走。模型密钥和数据源连接串是用它加密后存进库里的，只有库、没有这把钥匙，那些配置读不出来。登录账号在库里，密码不用单独搬。
