# 干净库验收 Utopia

目标：用**空 Postgres + 空 `data/`** 把上游引擎跑起来，确认能注册、建库、配模型、上传、对话。  
**不要**灌旧 `kee.dump`（schema 已与 utopia 对齐线不兼容）。

## 0. 前置

1. 当前分支：`follow-utopia`
2. 打开 **Docker Desktop**（本机若 `docker info` 失败，先开 Docker 再往下）
3. 端口空闲：`1516`（应用）、`1517`（宿主机连库）

## 1. 清掉旧运行态（干净）

在仓库根目录执行。会删 compose 卷里的库，以及挂载的 `data/` 原文/索引。

```bash
# 停服务
docker compose --profile app down

# 删掉 Postgres 卷（真正的「干净库」）
docker compose --profile app down -v

# 清空运行目录（保留目录本身；勿删整个仓库）
rm -rf data/files data/index
# secret.key 若存在也删掉，让新部署重新生成
rm -f data/secret.key
```

可选：若曾用过旧镜像/卷名冲突，再确认：

```bash
docker volume ls | grep -i utopia
# 有残留且确认不要了：docker volume rm <名字>
```

`.env` 可保留。最少只需：

```bash
UTOPIA_DATABASE_URL=postgres://utopia:utopia@127.0.0.1:1517/utopia
```

（`docker compose --profile app` 时，容器内会用 compose 默认的 `postgres://utopia:…@db:5432/utopia`，宿主机这条主要给 `cargo run` 用。）

## 2. 启动（推荐：预构建镜像）

```bash
docker compose --profile app up -d
docker compose --profile app ps
docker compose --profile app logs -f app
```

看到迁移跑完、服务监听后：

- 打开 http://localhost:1516  
- **注册第一个账号** → 自动成系统管理员，并会有公共知识库  
- **管理 → 模型**：配 chat + embedding（任意 OpenAI 兼容端点）  
- 进某个 KB → 上传一小份 PDF/Markdown → 等处理完 → 对话问一句带引用的问题  

健康检查：

```bash
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:1516/
# 期望 200 或登录页相关 2xx/3xx，不是 connection refused
```

## 3. 备选：只起库 + 本地编译

适合改代码时。同样要先做完第 1 步的干净清理。

```bash
docker compose up -d db
# 等 healthy
docker compose ps

cargo run -p utopia-server
# 另开终端
cd web && pnpm install && pnpm dev
```

- API / 内嵌前端视绑定：默认后端 http://localhost:1516  
- Vite 开发：http://localhost:5173（代理 `/api`）

首次 `cargo run` 会自动跑迁移；`data/` 会在 CWD 下重建。

## 4. 验收清单（最小）

| # | 动作 | 通过标准 |
|---|---|---|
| 1 | 打开 1516 | 出注册/登录页 |
| 2 | 注册首账号 | 能进控制台 |
| 3 | 配模型 | 保存成功，无报错 |
| 4 | 上传文档 | 文库出现文档，状态到可检索 |
| 5 | 对话 | 有回答；有引用可点回原文（有模型时） |
| 6 |（可选）装示例本体 | 用本体工作台导入 `extensions/examples/demo-ontology/ontology.ttl` |

## 5. 常见坑

| 现象 | 处理 |
|---|---|
| `docker info` 失败 | 先开 Docker Desktop |
| 端口占用 | 改 `.env` 里绑定，或停掉旧 `utopia-server` / 旧 compose |
| 还想用旧 dump | **不要**；旧线迁移号与上游不一致。语料请重新上传 |
| 镜像拉不动 | 设 `UTOPIA_IMAGE` / `UTOPIA_DB_IMAGE`，或用第 3 节本地编译 |
| `down -v` 后仍像旧数据 | 检查是否清了 `./data`，以及是否连错端口上的别的 PG |

## 6. 做完怎么停

```bash
docker compose --profile app down
# 若还要盘干净（下次仍从零）：
docker compose --profile app down -v
```
